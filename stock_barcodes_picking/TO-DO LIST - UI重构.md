|---|---|---|---|

| 手机暗色模式 | `图片格式/手机暗色模式.png` | 视觉基准 | 卡片/文字反色，输入框与提示条保持浅色 |
| 平板竖屏模式 | `图片格式/平板竖屏模式.png` | 响应式基准 | **单列不变，仅横向拉伸**，无两栏 |
| 整体布局 | `整体布局/html/Index.html` | 结构 + 精确 px | 4 个画板：手机亮色 / 平板竖 / 平板横 / 手机暗色 |
| 元素展示 | `元素展示/html/Index.html` | 组件规格 | 按钮 5 态、卡片 3 类型、亮暗两套 |

补充结论：

1. 平板横屏（1228×800）仍是**单列**，与手机一致，只是容器变宽。
2. 暗色模式只存在于 `整体布局` 的 `18_8739` 画板，`元素展示` 里是同一套组件的亮/暗双份标注。
3. 浏览器打开 HTML 与 PNG 的差异，主要来自 Pixso 导出时**多层半透明背景叠加**，实测取色后以 PNG 为准（见第 2 节）。

## 4. 硬性边界（不可触碰）

1. **后端 Python 基本不动**：wizard 现有方法签名、`get_scan_state()` 返回字段完全不动。**唯一例外**（Q-6 已批准）：新增 `action_remove_package(package_id)`，仅清空包内明细的 `result_package_id`。
2. **JS 方法名不动**：只允许新增派生 getter / 辅助函数。
3. **state 字段不动**（`barcode_lot_scan_policy`…`_previousAction` 全部保留）。
4. **OWL 条件表达式逻辑不动**，只允许换嵌套位置。
5. **Bootstrap + Font Awesome 图标体系继续用**。
6. **RPC 调用 JSON 结构不动**。

### 4.1 JS 侧必须保留的 DOM 锚点

```javascript
document.querySelector(".o_picking_scan_moves");           // 产品列表容器
container.querySelector(`[data-scan-lot="${lotKey}"]`);    // 滚动定位到批次
container.querySelector(`[data-scan-row="${target.rowKey}"]`); // 滚动定位到行
```

## 6. 回归风险清单

- **双行 +1 重置 bug**：`move_line_ids` 为空的 confirmed move 已过滤，重构 `t-foreach` 时不能重新引入。
- **`action_add_move_quantity` 在 mandatory 下也生效**：非跟踪产品标题栏的 `+1` 必须保留。
- **受跟踪产品标题栏不放 `+1`**（全拣完会报错）：仍只在 `tracking === 'none'` 时渲染。
- **MRP 模块不受影响**：本次只改 `stock_barcodes_picking`。
- **`.o_picking_scan_moves` 必须仍是最外层滚动容器**，否则扫码后自动滚动定位失效。
