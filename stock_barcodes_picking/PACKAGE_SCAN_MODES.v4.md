## 0.2 数量追溯产品：按包裹拆行 + 需求拆分（v4.4）

- 同一 move 的数量追溯产品，按**目标包裹**拆成多行（对齐官方条码界面），并额外给「未装包剩余」一行：
  - 剩余行在上，包裹行在下；
  - 每行显示自己的已拣数量与需求。
- 需求按**装箱顺序**分配，**各行需求之和恒等于原单需求**：
  - 每行需求 = min(该包裹已装数量, 剩余未分配需求)；
  - 超拣部分只体现在「已拣」上，不会抬高需求；剩余行拿最后剩下的需求。
- 示例：
  - 需求 10、装包 4 → 剩余行 `已拣 0 / 需求 6`，包裹行 `已拣 4 / 需求 4`；
  - 需求 20、两包实际 13 / 14 → `13 / 13`、`14 / 7`。
- 「已拣」数字变蓝：按**本行**已拣 ≥ 本行需求判断。
- `+1`、修改、扫码 +1、拆包、取消拣货都**只作用于当前行**（包裹行只改该包裹；剩余行只改未装包明细）。
- 无未装包剩余、且需求已分配完时，不显示剩余行。

## 3. 动作与模式

### 3.1 更多… 菜单（最终 6 项，按条件显示）

| 项 | 类型 | 行为 |
|---|---|---|
| **添加产品** | 弹窗 | 添加不在单据上的产品（沿用现有 `action_add_product_to_picking`） |
| **选择包裹** | 弹窗 | 选已有包裹 → 执行**装包** |
| **移除包裹** | 弹窗 | 列出本单**目标包**（`result_package_id`）→ 选一个 → 二次确认 → 该包裹从本单所有行移除。只清目标包，**不动 quant、不动源包** |
| **扫描拆包** | 进入模式 | 数量追溯：扫产品=从包裹拆出 1 件到未装包（多包裹弹窗选包）；扫包裹=整包去包裹号 |
| **取消拣货** | 进入模式 | 数量追溯：扫产品=取消 1 件（多包裹弹窗选包）；扫包裹=整包取消；预留保留 |
| **退出当前模式** | 按钮 | 非 `default` 模式时出现，回到方向默认模式 |

### 3.2 模式状态机

| 模式 | 进入 | 扫产品/SN | 扫包裹 | 退出 |
|---|---|---|---|---|
| `default` | 默认 | 正常拣货 | 整包拣货 | — |
| `pack` | 底栏「装包」 | 正常（不消费） | 装包 | 再点 / ✕ / 切单 / 「返回拣货模式」 |
| `split_scan` | 更多→扫描拆包 | 该行去包裹号 | 整包去包裹号 | ✕ / 切单 / 「返回拣货模式」 |
| `unclaim_scan` | 更多→取消拣货 | 该行 `picked=False` | 整包取消拣货 | ✕ / 切单 / 「返回拣货模式」 |

**默认模式按单据方向**：收货 `incoming` → `pack`；发货 `outgoing` / 调拨 `internal` → `default`。切单重算。

### 3.3 状态反馈

> 最终实现：提示条为**三行纵向**（模式提示 / 操作提示 / 当前操作），无 ✕；模式通过底栏「退出当前模式」切换。见 §0.1。

| 状态 | 信息框 | 底栏 |
|---|---|---|
| `default` | `扫包裹 = 整包拣货` | 更多… / 新包裹 / 装包 / 验证 |
| `pack` | `装包中：扫描或选择目标包裹`（蓝框 + ✕） | **返回拣货模式** / 新包裹 / 装包中… / 验证 |
| `split_scan` | `拆包中：扫描产品或包裹，去掉包裹号`（橙框 + ✕） | **返回拣货模式** / … |
| `unclaim_scan` | `取消拣货中：扫描产品或包裹，取消拣货（预留保留）`（橙框 + ✕） | **返回拣货模式** / … |
| 跨单占用 | `SN 0001 仍被 WH/OUT/00053 预留…`（红框） | 顶栏下「确认拣货」按钮 |

### 3.4 写入规则

**扫描拆包（split_scan）**
- 扫产品（数量追溯）：从该产品已装包的行中拆出 **1 件**：
  - 包裹行数量 −1；未装包处 +1（无散件行则新建）；
  - **已拣总数不变**，只改变包裹归属；
  - 若产品分布在多个包裹：**不写入**，弹窗列出包裹及已装数量，选择后再拆；
  - 仅一个包裹：扫描即拆 1 件。
- 扫产品（批次/序列号）：维持原逻辑，去掉该产品已装包行的 `result_package_id`。
- 扫包裹：该包裹在本单所有行 `result_package_id = False`。
- 无已装包行 → 提示「没有可拆的包裹」。

**取消拣货（unclaim_scan）**
- 扫产品（数量追溯）：取消 **1 件**（`quantity −1`，减到 0 时 `picked=False`，行保留）：
  - 若分布在多个包裹：**不写入**，弹窗选包裹，选择后再取消 1 件；
  - 仅一个包裹：扫描即取消 1 件。
- 扫产品（批次/序列号）：该产品已拣行 `picked = False`。
- 扫包裹：整包取消拣货；**不删行、不动预留**。
- 无已拣行 → 提示「没有可取消的拣货」。

**装包（pack）**
- 沿用 `_bind_to_package`：已拣未装包的行绑到目标包裹。

**移除包裹（弹窗）**
- 弹窗内容：本单的**目标包**（`result_package_id` 去重），显示 `包裹名 · 行数 · 数量`。
- 选中一个 → 提示「将把 XXXXXXX 从本单 N 行中移除，确定？」→ 确认后执行。
- 写入：该包裹在本单**所有行**（含未拣）`result_package_id = False`。
- `package_id`（源包）**保留**；quant 不动，见 Q11。
- 执行后信息框提示「已从 N 行移除包裹 XXXXXXX」。

> **与官方 `stock.package.unpack()` 的区别**（v4.3 补充）
>
> | 维度 | 本模块「移除包裹」 | 官方 `unpack()` |
> |---|---|---|
> | 对象 | 本单的 `stock.move.line` | `stock.quant`（库存实物） |
> | 实现 | 清 `result_package_id` | 立刻生成库存移动，把 quant 移出包裹 |
> | 影响 quant | 否 | 是（不可逆） |
> | 影响本单行 | 是 | **否**（行仍引用原包裹，易致验证异常） |
> | 适用 | 拣货中调整包装归属 | 包裹管理页、货未被预留时 |
>
> 因此扫码页不做实物解包；需要实物解包时，在包裹表单点官方「拆包」按钮。

## 4. 行编辑弹窗（对齐官方）

点行内 ✎ 打开，字段：

| 字段 | 一期 | 说明 |
|---|---|---|
| 数量 | ✅ | 序列号固定 1；数量追溯行 = 本行已拣总量 |
| 批次/序列号 | ✅ | 切换或新建（受 `use_create_lots`）；**数量追溯行不显示** |
| 包裹号 | ✅ | 源包 + 目标包；只作用于**当前行**的已拣明细 |
| 产品 | ⏸ 二期 | 换行需重算需求/预留，风险高 |

> v4.4 补充：
> - 数量追溯行编辑的是“该行”（包裹行或未装包剩余行），不会改到其它包裹；
> - 包名留空 = 不改动（不会清空包裹）；填写后应用到该行全部已拣明细；
> - 「保存 / 取消」同样式，跟随主题（不再使用未定义的 `--scan-primary`）。
